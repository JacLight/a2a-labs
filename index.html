LAB 06

The smallest A2A server

What the video showed

To offer your agent you publish an Agent Card and run an A2A server. The SDK handles the protocol; you write the executor, the code that runs when a job arrives.

Run it

python lab06_serve.py

It starts its own server on a free local port, sends one message, prints the reply and stops. Sample output: out/lab06.txt.

What to look for

  • [1]: one server, two addresses: the card at /.well-known/agent-card.json (served by create_agent_card_routes) and the JSON-RPC endpoint at / (served by create_jsonrpc_routes).
  • In the code, DefaultRequestHandler(agent_executor=..., task_store=InMemoryTaskStore(), agent_card=card) is the SDK part. You don't write any protocol handling.
  • HelloExecutor.execute is your part: it creates a task, calls HelloAgent().invoke(...), adds the result as an artifact and sets the task to completed.
  • [3]: the caller gets back a task in TASK_STATE_COMPLETED with the agent's text as its artifact.
  • HelloAgent stands for your agent. It could be built with any framework, or none.

Try this

  • Change the text that HelloAgent.invoke returns, run again, and see it in the artifact: line.
  • Send 'how are you' instead of 'hi' (the second example listed on the card's skill).
The code lab06_serve.py
"""Lab 06 (video section s06): the smallest A2A server.

Two things make your agent available: an Agent Card, and an A2A server that
receives jobs, runs them with your agent and reports back. The SDK does the
protocol; you write the executor: what happens when a job arrives.
Adapted from the official A2A Hello World sample (a2a-sdk 1.3.0).
"""
import asyncio, socket
import uvicorn
from starlette.applications import Starlette
from a2a.client import ClientConfig, create_client
from a2a.helpers import (get_artifact_text, get_message_text, new_task_from_user_message,
                         new_text_message, new_text_part)
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore, TaskUpdater
from a2a.types import (AgentCapabilities, AgentCard, AgentInterface, AgentSkill, Role,
                       SendMessageRequest, TaskState)

with socket.socket() as s:                       # pick a free port on this machine
    s.bind(('127.0.0.1', 0)); PORT = s.getsockname()[1]
URL = f'http://127.0.0.1:{PORT}'


class HelloAgent:                                # "your agent": any code, any framework, or none
    async def invoke(self, text: str) -> str:
        return f'Hello, World! I have received your request ({text})'


class HelloExecutor(AgentExecutor):              # your code: the bridge between A2A and your agent
    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        task = context.current_task or new_task_from_user_message(context.message)
        if not context.current_task:
            await event_queue.enqueue_event(task)
        updater = TaskUpdater(event_queue=event_queue, task_id=task.id, context_id=task.context_id)
        result = await HelloAgent().invoke(get_message_text(context.message))
        await updater.add_artifact(parts=[new_text_part(text=result, media_type='text/plain')])
        await updater.update_status(state=TaskState.TASK_STATE_COMPLETED)

    async def cancel(self, context: RequestContext, event_queue: EventQueue) -> None:
        raise NotImplementedError('Cancel is not supported.')   # same choice as the sample


# Part 1: the Agent Card (who you are, what you do, where to reach you).
card = AgentCard(
    name='Hello World Agent', description='Just a hello world agent', version='0.0.1',
    default_input_modes=['text/plain'], default_output_modes=['text/plain'],
    capabilities=AgentCapabilities(streaming=False),
    supported_interfaces=[AgentInterface(protocol_binding='JSONRPC', url=URL, protocol_version='1.0')],
    skills=[AgentSkill(id='echo_bot', name='Echo Bot', description='Replies with a hello.',
                       tags=['echo'], examples=['hi', 'how are you'])])

# Part 2: the A2A server. The SDK's request handler runs your executor and keeps tasks in a store.
handler = DefaultRequestHandler(agent_executor=HelloExecutor(), task_store=InMemoryTaskStore(),
                                agent_card=card)
app = Starlette(routes=[*create_agent_card_routes(card), *create_jsonrpc_routes(handler, '/')])


async def main():
    server = uvicorn.Server(uvicorn.Config(app, host='127.0.0.1', port=PORT, log_level='warning'))
    serving = asyncio.create_task(server.serve())
    while not server.started:
        await asyncio.sleep(0.05)
    print(f'[1] server up at {URL}')
    print(f'    card:     {URL}/.well-known/agent-card.json')
    print(f'    JSON-RPC: {URL}/')

    # A caller: read the card from the URL, then send one message.
    client = await create_client(URL, client_config=ClientConfig(streaming=False))
    print('[2] send "hi"')
    request = SendMessageRequest(message=new_text_message('hi', role=Role.ROLE_USER))
    async for response in client.send_message(request):
        task = response.task
        print(f'[3] reply: task {task.id[:8]}...  state {TaskState.Name(task.status.state)}')
        print(f'    artifact: {get_artifact_text(task.artifacts[0])}')
    await client.close()

    server.should_exit = True
    await serving
    print('[4] server stopped')


asyncio.run(main())

LAB 07

Writing your Agent Card

What the video showed

Callers read your card to decide whether to send you a job: your skills, the content you take and return, the extras you support, where you can be reached and how to sign in. Extra details for signed-in callers go in an extended card.

Run it

python lab07_agent_card.py

Sample output: out/lab07.txt.

What to look for

  • [1] fetches the card with plain httpx, with no A2A library on the caller side. It's just JSON at /.well-known/agent-card.json.
  • The numbered comments # 1. to # 5. in the card code match the card's parts: skills (name, description, examples), content types (text/plain), capabilities (streaming, pushNotifications, extendedAgentCard), the interface (JSONRPC, URL, A2A 1.0) and the sign-in scheme.

  • [2] without a token the extended card request gets HTTP 401; [3] with the example token it returns the extended card with the extra skill Echo Bot (Super Mode).
  • The comment above BearerCheck: the spec says the extended card MUST require authentication, but the SDK serves it to any request that reaches the route. Here the check is done by plain Starlette middleware.

LAB 08

Handling a job

What the video showed

You write an agent executor with two methods, execute and cancel. In execute you get or create the task, set it to working with a short status message, run your agent, add the result as an artifact and set it to completed. A streaming caller sees each step; a non-streaming caller gets the final task. A quick answer can be a single message, with no task.

Run it

python lab08_executor.py

Sample output: out/lab08.txt.

What to look for

  • [1] the streaming caller receives four things in order: the new task (SUBMITTED), WORKING with "Processing request...", the artifact, then COMPLETED with "Request is completed!".
  • Each of those lines comes from one line of HelloExecutor.execute: enqueue_event(task), update_status(WORKING), add_artifact(...), update_status(COMPLETED).
  • [2] the non-streaming caller sends the same message and gets one task, already completed, with the artifact inside. The SDK gathered the steps for it.
  • [3] for "ping" the executor enqueues a Message instead of a task, and the caller gets that message.
  • [4] lists the tasks in the store: only the two "hi" jobs are there. The "ping" reply made no task.

Try this

  • Delete the update_status(state=TaskState.TASK_STATE_WORKING, ...) call and see the streaming caller get one event fewer.
  • Set AgentCapabilities(streaming=False) on the card. The SDK client then doesn't stream, so [1] prints a single completed task like [2].

"""Lab 08 (video section s08): handling a job.

You write an agent executor with two methods: execute (incoming messages) and
cancel. The SDK's request handler calls them and keeps tasks in a task store.
execute: get or create the task -> WORKING with a status message -> run your
agent -> add its result as an artifact -> COMPLETED. A streaming caller sees
each step; a non-streaming caller gets the final task. A quick answer can be a
single Message, and then no task is created.
"""
import asyncio, socket
import uvicorn
from starlette.applications import Starlette
from a2a.client import ClientConfig, create_client
from a2a.helpers import (get_artifact_text, get_message_text, new_task_from_user_message,
                         new_text_message, new_text_part)
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore, TaskUpdater
from a2a.types import (AgentCapabilities, AgentCard, AgentInterface, AgentSkill, ListTasksRequest, Role,
                       SendMessageRequest, TaskState)

with socket.socket() as s:
    s.bind(('127.0.0.1', 0)); PORT = s.getsockname()[1]
URL = f'http://127.0.0.1:{PORT}'


class HelloAgent:                                 # stands in for an agent you already have
    async def invoke(self, user_request: str) -> str:   # (LangGraph, CrewAI, your own code...)
        return f'Hello, World! I have received your request ({user_request})'


class HelloExecutor(AgentExecutor):
    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        query = get_message_text(context.message)
        if query == 'ping':                       # quick answer, nothing to track: reply with a Message
            await event_queue.enqueue_event(new_text_message('pong', role=Role.ROLE_AGENT))
            return
        task = context.current_task               # the task, if this message continues one
        if not task:                              # no task yet: create one
            task = new_task_from_user_message(context.message)
            await event_queue.enqueue_event(task)
        updater = TaskUpdater(event_queue=event_queue, task_id=task.id, context_id=task.context_id)
        await updater.update_status(state=TaskState.TASK_STATE_WORKING,
                                    message=new_text_message('Processing request...'))
        result = await HelloAgent().invoke(user_request=query)          # run your agent
        await updater.add_artifact(parts=[new_text_part(text=result, media_type='text/plain')])
        await updater.update_status(state=TaskState.TASK_STATE_COMPLETED,
                                    message=new_text_message('Request is completed!'))

        raise NotImplementedError('Cancel is not supported.')         # lab 09 covers cancel

def describe(event) -> str:                       # one line per thing the caller receives
    kind = event.WhichOneof('payload')
    if kind == 'task':
        t = event.task
        line = f'task          {TaskState.Name(t.status.state)}'
        return line + (f'  artifact: "{get_artifact_text(t.artifacts[0])}"' if t.artifacts else '')
    if kind == 'status_update':
        st = event.status_update.status
        return f'status_update {TaskState.Name(st.state)}  "{get_message_text(st.message)}"'
    if kind == 'artifact_update':
        return f'artifact_update "{get_artifact_text(event.artifact_update.artifact)}"'
    return f'message       "{get_message_text(event.message)}"  (no task created)'


async def send(text: str, streaming: bool):
    client = await create_client(card, client_config=ClientConfig(streaming=streaming))
    request = SendMessageRequest(message=new_text_message(text, role=Role.ROLE_USER))
    async for event in client.send_message(request):
        print('    ' + describe(event))
    await client.close()

    tasks = (await client.list_tasks(ListTasksRequest())).tasks
    print(f'[4] tasks in the store: {len(tasks)} (the two "hi" jobs; "ping" made none)')
    await client.close()
    server.should_exit = True
    await serving


asyncio.run(main())

LAB 09

Stopping to ask, and cancels

What the video showed

When your agent needs more from the caller, set the task to input required with the question in the status message. The answer comes back on the same task and execute runs again. When a caller cancels, the SDK calls your cancel method. There you can try to stop the work and set the task to canceled, or refuse.

Run it

python lab09_pause_and_cancel.py

Sample output: out/lab09.txt. It takes well under a second, even though the "long job" would sleep for 60 seconds: the cancel stops it.

What to look for

  • [1] the task stops at TASK_STATE_INPUT_REQUIRED and its status message is the question (the one from the official LangGraph currency sample).
  • [2] the answer "EUR" is sent with the same task ID (see send(client, 'EUR', task)); the same task ID then shows COMPLETED with the result.
  • [3] is way 1. Converter.cancel sets TASK_STATE_CANCELED, and the caller gets the canceled task back.
  • [4] is way 2. RefusingConverter.cancel raises UnsupportedOperationError (the 1.3.0 way of writing the LangGraph sample's refusal). What a2a-sdk 1.3.0 does with that: the caller gets TaskNotCancelableError, and the task is left FAILED. That is this SDK's behaviour, shown as it really runs.
  • Both copies of the agent run in one Starlette app on two paths (/stops, /refuses) so you can compare them.

Try this

  • Make RefusingConverter.cancel raise NotImplementedError('Cancel is not supported.') like the Hello World sample. In 1.3.0 the caller then gets InternalError instead.
  • Change the question text in the INPUT_REQUIRED branch, or answer "JPY" in step [2].
The code lab09_pause_and_cancel.py
"""Lab 09 (video section s09): stopping to ask, and cancels.

If your agent needs more from the caller, set the task to INPUT_REQUIRED and
put the question in the status message. The answer arrives as a new message on
the same task, and execute runs again with that task.
When a caller cancels, the SDK calls your cancel method. There you can try to
stop the work and set CANCELED, or refuse (as the official samples do).
"""
import asyncio, logging, socket
import uvicorn
from starlette.applications import Starlette
from a2a.client import ClientConfig, create_client
from a2a.helpers import (get_artifact_text, get_message_text, new_task_from_user_message,
                         new_text_message, new_text_part)
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore, TaskUpdater
from a2a.types import (AgentCapabilities, AgentCard, AgentInterface, AgentSkill, CancelTaskRequest,
                       GetTaskRequest, Role, SendMessageRequest, TaskState)
from a2a.utils.errors import UnsupportedOperationError

with socket.socket() as s:
    s.bind(('127.0.0.1', 0)); PORT = s.getsockname()[1]
URL = f'http://127.0.0.1:{PORT}'
logging.getLogger('a2a').setLevel(logging.CRITICAL)   # the SDK logs a refused cancel with a full traceback


class Converter(AgentExecutor):
    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        text = get_message_text(context.message)
        task = context.current_task
        if not task:
            task = new_task_from_user_message(context.message)
            await event_queue.enqueue_event(task)
        up = TaskUpdater(event_queue=event_queue, task_id=task.id, context_id=task.context_id)
        await up.update_status(state=TaskState.TASK_STATE_WORKING)
        if text == 'Convert every price list':        # a long job (used for the cancel demo)
            await asyncio.sleep(60)
        elif text == 'Convert 100 USD':               # target currency missing: stop and ask
            await up.update_status(state=TaskState.TASK_STATE_INPUT_REQUIRED, message=new_text_message(
                'To which currency would you like to convert?', task_id=task.id, context_id=task.context_id))
        else:                                         # the answer, on the same task
            await up.add_artifact(parts=[new_text_part(f'100 USD = 92 {text} (example rate)')])
            await up.update_status(state=TaskState.TASK_STATE_COMPLETED)

What the video showed

Before your agent hands a job to another agent, it needs that agent's card. The standard place to look is the agent's own domain at /.well-known/agent-card.json; a registry or your own configuration are other ways to get it. Your agent reads the card the way it will use it, then creates its client from the card.

What to look for

  • [1]: A2ACardResolver(httpx_client=..., base_url=URL).get_agent_card() fetches the card from the well-known path. You give it only the base address.

LAB 12

Sending the job

What the video showed

A job goes out as a message made of parts: text, a file (as bytes or a link) or structured data, each with an optional media type. What comes back is either a Message or a Task. The remote agent decides which, so your code handles both. By default the call waits; with returnImmediately you get the task back as soon as it exists and follow it yourself. acceptedOutputModes tells the agent which media types you accept.

Run it

python lab12_message_or_task.py

Sample output: out/lab12.txt.

What to look for

  • show(reply) is the "handle both" code: reply.HasField('message') means a direct answer with nothing to track; otherwise reply.task has an id and a context_id.
  • [1]: a plain question gets a Message back. That was the stand-in's choice; another agent could have made a task.
  • [2]: one message, three parts: text, raw (the image bytes, image/png, with a filename) and data. Use new_url_part(...) instead of new_raw_part(...) to send a file as a link.
  • [3]: the default call took about 1.2 s and came back COMPLETED. It waits until the task finishes or pauses.
  • [4]: with return_immediately=True the task came back at once as SUBMITTED. The loop then checks it with get_task until it is final (SUBMITTED -> WORKING -> COMPLETED). Checking is one way to follow a task; streaming and push notifications are covered in labs 17 and 18.
  • [3] vs [4]: the stand-in reads accepted_output_modes and returns a data part for application/json and a text part for text/plain. Agents SHOULD use this to tailor their output. It's a hint, not a guarantee.

  • In [3], set return_immediately=True and watch the after ...s time drop to 0.0 and the state change to SUBMITTED.
  • Remove the new_raw_part(...) line from the job and see the stand-in answer with a Message instead of a Task.

"""Lab 12 (video section s12): sending the job.

A message is made of parts (text, a file as bytes or a link, structured data).
What comes back is either a Message or a Task; the remote agent decides, so the
client handles both. The default call waits; returnImmediately gets the task back
at once. acceptedOutputModes lists the media types you accept.

import asyncio, socket, time
import httpx, uvicorn
from starlette.applications import Starlette
from a2a.client import A2ACardResolver, ClientConfig, create_client
from a2a.helpers import (new_data_part, new_message, new_raw_part, new_task_from_user_message,

                       Role, SendMessageConfiguration, SendMessageRequest, TaskState)

FINAL = {TaskState.TASK_STATE_COMPLETED, TaskState.TASK_STATE_FAILED,
         TaskState.TASK_STATE_CANCELED, TaskState.TASK_STATE_REJECTED}
PAUSED = {TaskState.TASK_STATE_INPUT_REQUIRED, TaskState.TASK_STATE_AUTH_REQUIRED}
st = TaskState.Name

def show(reply):
    """The answer is a Message (nothing to track) or a Task (track it by id)."""
    if reply.HasField('message'):
        return f'Message: "{reply.message.parts[0].text}"'
    t = reply.task
    return f'Task id={t.id[:8]}.. contextId={t.context_id[:8]}.. state={st(t.status.state)}'

async def send(client, msg, **config):
    req = SendMessageRequest(message=msg, configuration=SendMessageConfiguration(**config))
    return [r async for r in client.send_message(req)][-1]   # non-streaming: one reply

async def main():
    async with httpx.AsyncClient(timeout=10) as http:
        card = await A2ACardResolver(http, URL).get_agent_card()
        client = await create_client(card, client_config=ClientConfig(httpx_client=http, streaming=False))

        print('[1] a quick question, nothing to track')
        print('   ', show(await send(client, new_text_message('Are you open today?', role=Role.ROLE_USER))))

        job = lambda: new_message(role=Role.ROLE_USER, parts=[
            new_text_part('Analyze this image and highlight any faces.'),
            new_raw_part(b'\x89PNG\r\n\x1a\n...', media_type='image/png', filename='input_image.png'),
            new_data_part({'max_faces': 5})])
        print('[2] a job: parts =', [p.WhichOneof('content') for p in job().parts])

        print(f'    after {time.time() - t0:.1f}s:', show(reply))
        print('    accepted application/json -> artifact part:', reply.task.artifacts[0].parts[0].WhichOneof('content'))

        print('    states seen while checking:', ' -> '.join(dict.fromkeys(seen + [st(task.status.state)])))
        print('    accepted text/plain -> artifact part:', task.artifacts[0].parts[0].WhichOneof('content'),
              f'"{task.artifacts[0].parts[0].text}"')
        await client.close()

    async def execute(self, ctx, q):
        if not any(p.raw for p in ctx.message.parts):
            await q.enqueue_event(new_text_message('Yes, until 18:00.', context_id=ctx.context_id))
            return

        await q.enqueue_event(task)
        up = TaskUpdater(q, task.id, task.context_id)
        await asyncio.sleep(0.4); await up.start_work()
        await asyncio.sleep(0.8)
        modes = list(ctx.configuration.accepted_output_modes) if ctx.configuration else []
        if 'application/json' in modes or not modes:

The states your code handles

What the video showed

Once you have a task, your code branches on its state, in four cases. Keep waiting: submitted, working. Paused, needs you: input required, auth required. Collect: completed. It's over: failed, canceled, rejected. Completed, failed, canceled and rejected are final, and a message sent to a final task gets an error. A waiting call also returns at a pause, not only at the end.

Run it

python lab13_states.py

It takes about 6 seconds. Sample output: out/lab13.txt.

What to look for

  • follow() is the four-way switch. KEEP_WAITING, PAUSED, COMPLETED and OVER match the four cases in the video.
  • [1]: six jobs, one per path. Each line shows the states the loop saw and what it did: collect, paused, needs you (with the question from the status message), or it's over.
  • The slow job is cancelled by the client while it's WORKING, so it ends CANCELED.
  • [2]: a default (waiting) call on a job that asks a question returns after about 0.7 s at INPUT_REQUIRED, before the job is done. Your code has to handle pauses as well as endings.
  • [3]: a message sent to the completed task is refused with UnsupportedOperationError ... is in terminal state: TASK_STATE_COMPLETED.
  • The two logging lines near the end hide a cleanup traceback that a2a-sdk 1.3.0 prints on the server side after [3]. They don't change what the client sees.

  • In [3], send the message to the paused task from [2] (task_id=task.id, context_id=task.context_id) instead of done. It's accepted, and the same task completes, because a paused task isn't final.
  • Remove 'slow' from the job list and return_immediately=True from the first loop. The calls now wait, so each line starts at the final or paused state. ('slow' is removed because a waiting call on it would block until the job ends.)

async def follow(client, task, stop=False):
    """The four-way switch. Returns the states seen and what the code did."""
    seen = []
    while True:
        s = task.status.state
        if not seen or seen[-1] != name(s): seen.append(name(s))

                await client.cancel_task(CancelTaskRequest(id=task.id))
            await asyncio.sleep(0.2)
            task = await client.get_task(GetTaskRequest(id=task.id)); continue
        if s in PAUSED:                             # can't finish until you act
            return seen, f'paused, needs you: "{get_message_text(task.status.message)}"'
        if s == S.TASK_STATE_COMPLETED:             # collect the artifacts
            return seen, f'collect: {[a.name for a in task.artifacts]}'
        if s in OVER:                               # error, stopped, or turned down

            return seen, f"it's over {why}".rstrip()

What the video showed

In auth required, the remote agent needs permission to continue, and its status message says what it needs. The credential normally doesn't travel inside an A2A message. It reaches the agent by a separate, secure route, such as an OAuth sign-in, unless both sides have agreed on another way. Getting the results

What the video showed

When a task completes, its artifacts are the output, and each one can hold text, files or data. The agent's messages are progress and questions; the agent decides which it keeps in the task's history, so don't count on finding one there later. You can fetch a task by ID with as much recent history as you want, up to what the agent keeps. You can list the tasks you've started, filtered by conversation or state, newest first.

What to look for

  • [1]: three artifacts, each with a different kind of part: url (a file by link, image/png), data (application/json) and text.
  • [2]: with historyLength not set you get everything this agent kept (your message plus two progress messages). 1 gives the most recent one; 0 gives none. historyLength is a maximum, and an agent may return fewer.
  • [2]: the last message, "Done.", is the current status message. In this SDK it isn't in the history list. That's one reason not to rely on history for results.

  • You see only the tasks the agent's rules let you see. The SDK's in-memory store keys tasks by the caller's identity; this lab has a single caller, so it sees all of them.

Live updates with streaming

What the video showed

To stream, check that the card supports it and send with streaming on. In the Python SDK, that's one setting on the client. The stream starts with the task, then brings a status update when the state changes and an artifact update when output is ready. Large outputs can arrive in pieces, with flags for "add this to the same artifact" and "this is the last piece". If the connection drops, subscribe to the task again: first you get the task as it is now, then the updates continue.

Run it

Sample output: out/lab17.txt.

What to look for

  • [1] and ClientConfig(..., streaming=True): the one setting. The SDK streams only if the card's capabilities.streaming is true too.
  • [2]: the order is the same as in the official Hello World tutorial: task SUBMITTED, status update WORKING "Processing request...", artifact updates, status update COMPLETED. Then the stream closes.
  • The three artifact updates carry append=False/True and last_chunk=True on the last one. show() adds pieces to the same artifact_id when append is true.
  • [3]: the client stops reading after the first piece and closes the stream (await stream.aclose()). The task keeps running on the agent.
  • (resubscribed) task WORKING (artifact so far: "Hello, World! "): after client.subscribe(...), the first event is the task snapshot, which already includes the piece sent while the client was away. Then the remaining updates arrive.

LAB 18

Callbacks with push notifications

What the video showed

Check that the card supports push notifications, then give the remote agent a webhook address and the credentials it should use when it calls you, in the first message or added to a task later. The agent sends updates to your webhook (the same kind of update a stream carries), and your webhook replies with a success code. The same update can arrive twice, and one can go missing. So check the credentials, check that the task ID is one you started, ignore duplicates, then fetch the task. If you offer push notifications, the spec recommends checking the webhook addresses callers give you.

Run it

python lab18_push.py

It runs two local servers: the stand-in agent and your webhook receiver. Sample output: out/lab18.txt.

What to look for

  • [2]: the push config goes in the first message: TaskPushNotificationConfig(url=WEBHOOK, authentication=AuthenticationInfo(scheme='Bearer', credentials=SECRET)). With return_immediately=True the task comes back SUBMITTED and no connection stays open.
  • webhook() checks the Authorization header first. A call with the wrong credentials gets 401. Everything else gets 200 straight away and is checked afterwards in check().
  • [3]: each notification is a StreamResponse: task, statusUpdate or artifactUpdate. The fake call about "not-mine" is ignored because it isn't a task this client started.
  • statusUpdate duplicate, ignored: the stand-in's RetryingSender sends the final update twice, as a retry would. The client recognises the same body and drops it. Then GetTask fetches the full result.
  • [4], agent side: the SDK's validate_push_notification_url rejects private, link-local and loopback addresses, and registering http://192.168.1.10/hook fails with InvalidParamsError. The lab's own webhook is on 127.0.0.1, so allowed() allow-lists that one exact address (see the comment there).

Try this

  • In [2], change credentials=SECRET to credentials='wrong' and run again. The agent's calls now get 401, nothing reaches [3] except the fake call, and the SDK logs each failed delivery. GetTask still gets the result.
  • Add the webhook to the task after it exists instead: send without task_push_notification_config, then set push.task_id = task.id and call await client.create_task_push_notification_config(push). Notifications sent before you registered (here, the first task one) don't reach you.

Cancelling, and follow-ups

What the video showed

To stop a job, cancel the task. It's a request, and the agent may not be able to stop. If it can, you get the task back, now canceled. If it can't, for example because the task already finished, you get an error. A finished task can't be reopened. Securing your agent

What the video showed

Three decisions: how callers sign in, what each caller may do, and what your card shows. Credentials travel with each request, not inside the A2A message. One caller can't see or cancel another caller's tasks, and such a task looks the same as one that doesn't exist.

Run it

What to look for

What the video showed

async def main():
    server = uvicorn.Server(uvicorn.Config(app, host='127.0.0.1', port=PORT, log_level='critical'))
    serving = asyncio.create_task(server.serve())
    while not server.started:
        await asyncio.sleep(0.05)

    print('[1] plain httpx SendMessage with different A2A-Version headers')
    async with httpx.AsyncClient() as http:
        for version in ['1.0', '0.5', '1.1', None]:
            headers = {'A2A-Version': version, 'A2A-Extensions': CITE} if version else {'A2A-Extensions': CITE}
            reply = (await http.post(URL, json=BODY, headers=headers)).json()
            err = reply.get('error')
            result = f"error {err['code']}: {err['message']}" if err else 'ok'
            print(f"    A2A-Version {version or '(none)':<6} -> {result}")
    # The spec: match Major.Minor, and read an empty header as 0.3. What 1.3.0 really does: it reads
    # no header as 0.3 (refused here; the routes take enable_v0_3_compat=True to serve 0.3 callers),
    # but it compares only the major number, so 1.1 is accepted and handled as 1.0.

    print('[2] SDK client (adds A2A-Version itself), opting in to both extensions')
    client = await create_client(card, client_config=ClientConfig(streaming=False))
    msg = new_text_message('Find restaurants near me', role=Role.ROLE_USER)
    msg.extensions.append(GEO)
    msg.metadata.update({GEO: {'latitude': 37.7749, 'longitude': -122.4194}})   # the extension's data
    both = ClientCallContext(service_parameters={'A2A-Extensions': f'{GEO},{CITE}'})
    async for event in client.send_message(SendMessageRequest(message=msg), context=both):
        print(f'    reply: {get_message_text(event.message)}')

    print('[3] same request, opting in to geolocation only (citations is required)')
    geo_only = ClientCallContext(service_parameters={'A2A-Extensions': GEO})
    try:
        async for event in client.send_message(SendMessageRequest(message=msg), context=geo_only):
            print(f'    reply: {get_message_text(event.message)}')
    except Exception as e:
        print(f'    caller gets: {type(e).__name__}: {e}')
    await client.close()
    server.should_exit = True
    await serving


asyncio.run(main())
